<p class="section-kicker not-content">From nothing to ranked results</p>

<Code code={`# 1. Install. No Rust toolchain needed.
curl -fsSL https://raw.githubusercontent.com/duckedup/nidus/main/install.sh | sh

# 2. Index this repo. AST-aware, and with no API key it answers from BM25.
nidus code ingest . --dir ./store

# 3. Ask it a question.
nidus code search "where do we fsync the write-ahead log" --dir ./store`} lang="bash" />

<p class="section-kicker not-content">Four ways in, one store directory</p>

<div class="lane-grid not-content">
  <article class="lane" data-reveal>
    <span class="lane-kicker">nidus ingest</span>
    <h3>Index a folder, search it</h3>
    <p>
      One command walks the tree, chunks every file, embeds it and stores it. Re-run it
      and nothing unchanged is touched. Bring an embedding provider to search by
      meaning, or skip it entirely and get BM25 with no API key.
    </p>
    <a class="lane-link" href="/guides/ingest/">Ingest a directory</a>
  </article>

  <article class="lane" data-reveal style="--reveal-delay:0.04s">
    <span class="lane-kicker">nidus code</span>
    <h3>Search a codebase</h3>
    <p>
      Chunked by symbol, not by byte count. Every hit names a function, its kind and
      its line span, so you land on the right lines instead of a paragraph near them.
    </p>
    <a class="lane-link" href="/guides/code/">Code search</a>
  </article>

  <article class="lane" data-reveal style="--reveal-delay:0.08s">
    <span class="lane-kicker">nidus serve</span>
    <h3>Serve it over HTTP</h3>
    <p>
      The same store on a port, in JSON. Every library operation has a route, so any
      language can drive it. The JavaScript, Go and Python SDKs speak to exactly this.
    </p>
    <a class="lane-link" href="/guides/http-server/">HTTP server</a>
  </article>

  <article class="lane" data-reveal style="--reveal-delay:0.12s">
    <span class="lane-kicker">nidus mcp</span>
    <h3>Give an agent memory</h3>
    <p>
      One line registers the store with any MCP client, over stdio or at
      <code>/mcp</code>. Your agent remembers what is worth keeping and recalls it by
      meaning, with no glue code.
    </p>
    <a class="lane-link" href="/guides/mcp/">MCP (agent memory)</a>
  </article>
</div>

<p class="section-kicker not-content">Why it exists</p>

<div class="feature-grid not-content">
  <article class="feature" data-reveal>
    <span class="twig" aria-hidden="true">❧</span>
    <h3>One binary, every door</h3>
    <p>
      <code>cargo install nidus</code> ships all 33 subcommands, the server, the MCP
      endpoint and every embedding provider. No feature flags to remember, and the
      prebuilt binaries are the same thing. Want only the store?
      <code>--no-default-features</code> is four crates and nothing else.
    </p>
  </article>
  <article class="feature" data-reveal style="--reveal-delay:0.04s">
    <span class="twig" aria-hidden="true">❧</span>
    <h3>Search by meaning, by keyword, or both</h3>
    <p>
      Vector search by cosine, dot or Euclidean distance, exact by default and
      HNSW/IVF when you want more speed. BM25 over the same records, hybrid queries
      that fuse the two, and typed metadata filters that narrow results before they
      score.
    </p>
  </article>
  <article class="feature" data-reveal style="--reveal-delay:0.08s">
    <span class="twig" aria-hidden="true">❧</span>
    <h3>One directory, crash-safe</h3>
    <p>
      A whole store is a single append-only directory, fsync'd per batch and
      CRC-checked. A crash loses at most the in-flight write, and a torn tail repairs
      itself the moment you reopen; nothing to back up but a folder.
    </p>
  </article>
  <article class="feature" data-reveal style="--reveal-delay:0.12s">
    <span class="twig" aria-hidden="true">❧</span>
    <h3>From a folder to the cloud</h3>
    <p>
      Start against a local directory, then move the same store to S3 or GCS by
      changing one URL, and add a shared Redis/Valkey memory tier when instances need a
      warm working set: no migration, no rewrite. Begin on a laptop and grow into the
      cloud when you need to.
    </p>
  </article>
</div>
